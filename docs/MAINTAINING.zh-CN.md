# 维护公开文档

[English](MAINTAINING.md) · [文档目录](README.zh-CN.md)

面向修改正文、示例、导航或构建发布说明的贡献者。代码和提交要求见[贡献规范](../CONTRIBUTING.md)。
文档与代码修订一起维护，功能变更在同一 PR 更新相应指南。

## 职责与收录标准

| 位置 | 职责 |
| --- | --- |
| 根目录双语 README | 产品介绍、稳定入口与许可链接 |
| 根目录社区、安全与法律文件 | 贡献流程、漏洞披露与法律政策 |
| `docs/` | 经过评审的使用、构建、架构、测试和发布任务指南 |
| `docs/manifest.json` | 第一方正文公开清单、读者和语言对应 |
| 按需建立的 `docs/decisions/` | 经评审的长期架构决策，从架构页引用 |
| `.local/plans/`、`.local/notes/`、`.local/prototypes/` | Spec、执行计划、调试笔记与实验 |
| `.local/validation/`、`.local/archive/` | 原始证据及附件、保留的原稿与搬迁记录 |
| `third_party/` | 上游原始法律文本，不适用第一方正文收录规则 |

仓库没有文档站构建，不创建空分区、重复手册或虚构站点部署能力。
每个主题每种语言只有一份正文，其他位置通过链接引用。
易变接口细节引用代码或 Schema，人工表格不能称为完整自动生成 API 文档。
公开示例使用合成数据，不含凭据、私有媒体或作者机器绝对路径。

实现前先用本地 Spec 明确行为和决策。团队决策同时通过 Issue、PR 或团队平台共享，
`.local/` 不能成为唯一协作位置。仅将经过评审、符合实现的内容提升为正式指南。
长期取舍纳入 ADR；提案单独标明，不作为已交付功能。临时执行清单留在本地。

## 更新与验证

1. 阅读相关实现、测试、构建设置和工作流，明确读者、前提、支持范围、步骤、结果、恢复与限制。
   不把路线图内容写成已实现功能。
2. 搬迁前在 `.local/archive/` 保留原稿并记录新旧路径。搬迁或忽略不会清除 Git 历史。
3. 同步双语正文、对应页切换和任务目录。根目录英文政策及法律文本为准，不能仅改日期伪装翻译更新。
   有效 URL 调整时保留链接页或锚点。
4. 将每篇第一方正文以读者及翻译关系（或明确单语政策）加入清单；收录前评审差异，
   不能为通过检查把全部本地文件加入清单。
5. 安装[共享依赖](BUILDING.zh-CN.md)后运行：

```sh
npm run lint:docs
python scripts/check_documentation.py
python scripts/check_repository.py
python -m unittest discover -s scripts/tests
python scripts/dev.py check
```

修改安装或教程后，还须在隔离的全新环境严格执行步骤，再运行受影响的[行为与平台测试](TESTING.zh-CN.md)。
准确结果、跳过项和缓存使用留在 `.local/validation/`，PR 只附脱敏摘要。
示例按需写全目标文件、导入、依赖接线、配置、权限、迁移、运行和验证步骤；尽量维护一份示例源供各语言引用。
自动测试不能代替内容评审。

## 公开与打包范围

导航、Git 忽略、源码归档和应用打包分别控制：

- 清单和 Markdown 检查覆盖公开导航、链接、锚点与语言配对，拒绝未列出的第一方正文及指向本地私有文件的链接。
- `.gitignore` 防止普通暂存加入 `.local/`，仓库检查还会拒绝强制加入的私有资料；发布前审查候选差异及历史。
- `.gitattributes` 从 `git archive` 排除过程目录；归档检查器不解包即可检查实际源码 TAR 和 ZIP/APK/IPA 条目。
- `pubspec.yaml` 明确包含法律声明与内置模型资源，正式正文和过程证据不是应用资源。
  原生打包和真实发行文件仍需[发布检查](RELEASING.zh-CN.md)。

检查不覆盖外部 URL、翻译语义、全部 Markdown 扩展、截图、运行时权限或独立批准。
内部链接使用行内 Markdown 或引用定义，必要时使用明确的 HTML `id` 锚点。
未来增加文档站时，在发布前审查元信息、canonical、站点地图、语言对应、搜索、键盘、移动端、主题与减少动态效果；
仓库检查不代表这些站点能力已验证。

## 签名凭据

签名私钥、密钥库、密码、凭据配置、签名备份及备案资料不得纳入公开仓库或发行附件。
签名应用内嵌的公钥证书属于分发格式的一部分。

仓库和归档检查拦截常见签名输入，不能替代凭据审查。
CI 不将原始测试结果包或原生审计报告作为附件上传；公开 CI 日志不得包含凭据或私有应用数据。
