# Verify a change

[简体中文](TESTING.zh-CN.md) · [Documentation](README.md)

With `.venv` active, from the repository root:

```sh
python scripts/dev.py check
python scripts/dev.py test
```

Shared tests exercise observable behavior with synthetic data and fake providers;
they do not install apps, record audio, or call AI services. Generate deterministic
archive fixtures with `python scripts/generate_m2_contract_fixtures.py` and review
the resulting diff. Native Android exchange inputs are generated by `M3cContracts`;
iOS return fixtures use
`RunnerTests.testAndroidProducedArchivesImportAndReexportWithMediaAndSpeakerHistory`.
Native exporters include generated IDs/times, so validate payloads and assertions
rather than assuming reruns must be byte-identical. Retain strict invalid-container
rejection and never regenerate expected data merely to pass a failing test.

## Android

After preparing the Android toolchain, runtime, and models in the [build guide](BUILDING.md):

```sh
android/gradlew -p android -Ptarget-platform=android-arm64 :app:lintDebug :app:testDebugUnitTest :app:assembleDebugAndroidTest
```

This targets the application module, runs its lint/JVM tests, and compiles the
instrumentation APK; it does not run
instrumentation on a phone.

## iOS

For iOS, after [build preparation](BUILDING.md), choose an isolated
simulator from `xcrun simctl list devices available`, replace its ID, and run:

```sh
flutter build ios --debug --simulator --config-only --no-pub
xcodebuild test -workspace ios/Runner.xcworkspace -scheme Runner \
  -configuration Debug -destination 'platform=iOS Simulator,id=YOUR_SIMULATOR_ID' \
  -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO \
  -skip-testing:RunnerTests/RunnerTests/testCommittedAudioPlayerStartsWithDeviceOutputFormat
```

The skipped case requires an actual audio output route; check it separately on an
idle provisioned device without that exclusion. Native test-host results do not
replace signed-product acceptance. Microphone capture and fault injection require
explicit selection of an idle test device. Production builds must not enable
`MOMENTAI_INTERNAL_TESTS`. Store raw results under `.local/validation/` and report only sanitized,
accurate validation summaries in PRs or published release notes.

## Documentation and clean setup

`python scripts/dev.py check` includes Markdown style, publication manifest, internal
links/anchors, language pairs and public-source hygiene. These are structural checks,
not editorial approval. `python scripts/check_documentation.py --archive PATH` checks
an exported source TAR or application ZIP/APK/IPA for private process paths; a passing
result does not inspect signatures, permissions, or native linkage.

For setup acceptance, create a fresh checkout of the candidate revision under
`.local/validation/`, use a new virtual environment and fresh dependency caches,
then follow [Build from source](BUILDING.md) in order. Record exact tool versions,
commands, exit codes, cache/network use and any substitutions in local evidence.
A cached build must be labeled as such. Keep this checkout out of analysis and never
copy real recordings into it. App/device acceptance uses the synthetic first-recording
and transfer procedure in the [user guide](USAGE.md), including denied permissions,
interrupted recording and rejected import. Report unexecuted cases explicitly.
